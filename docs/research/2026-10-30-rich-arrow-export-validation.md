# Rich typed Arrow export validation — D01c2

This completes typed scalar/nested projection in the
[rich Arrow plan](../plans/2026-10-30-rich-arrow-source-port.md). Dynamic JSON
extension interop, arbitrary schemaless keys/missing distinctions, durable schema
and Lance history/format still remain open, as does the full product ledger.
No performance experiments or gate changes are included.

## Behavior

`scan_record_batches(payload_schema=...)` now accepts the existing four aliases,
real PyArrow scalar/nested DataTypes and Fields with matching names. Requested
nullability and metadata, including nested fields, are retained in a stable
schema for empty and filtered scans. No data-dependent inference occurs.

Mojo reads immutable native payload nodes and writes final owned Arrow buffers.
Struct projection selects declared keys in order; missing and explicit null map
to Arrow null. Required children fail only under an active parent. Lists preserve
null versus empty versus null elements; fixed-size lists check the stored length
and emit masked null placeholders when their parent is null. Empty structs and
zero-length fixed lists are supported. Unknown extensions are rejected rather
than silently interpreted as their storage type.

Signed, unsigned, float, bool and string families remain strict, preserving the
former scalar contracts. Integer narrowing checks bounds. Floating narrowing
matches the pinned Arrow conversion sequence and rejects nonfinite results under
Akasha's existing finite numeric contract. Arrow itself permits Infinity.

Scalar aliases and rich types share one exporter. Obsolete scalar-only native
column kinds and the previous scalar branch are removed. The existing recursive
C Data buffer owner is extracted unchanged into `arrow_buffers.mojo` and reused
by vector/payload export. No Python row values or staging arrays are constructed.
Payload output is owned; it retains no generation pin after materialization.

Nested output shares the aligned buffer budget and cancellation/deadline checks.
A separate bounded cell count prevents null-only fixed-list expansion from
allocating unbounded traversal state. The public API documents this limit; neither
it nor the buffer cap claims to bound total process RSS.

## Source evidence and correction

- Existing actual Arrow IPC/JSON fixture: four rows × 22 typed/nested columns,
  compared through native ingress and C Data export with matching schemas.
- New actual Arrow cast fixture: **2,126 finite Float64 inputs × two targets**.
  F16 has 1,128 finite / 998 overflow results; F32 has 1,256 finite / 870 overflow
  results. Every finite output is compared bit-for-bit and every overflow is
  checked for rejection.
- Arrow 58.4.0, half 2.7.1 and num-traits 0.2.19 match Lance's lock. Source
  archives and 198 original Rust files are hashed and verified. All seven Arrow
  dependencies are pinned; initial resolution of arrow-buffer 58.4.1 was corrected
  before acceptance, with identical cast expectations after regeneration.

The first exact comparison exposed four F16 midpoint differences. Arrow calls
`num_cast` → `half::NumCast::from`, whose implementation calls `to_f32()` before
`f16::from_f32()`. A direct F64→F16 cast differs. Writing both inline conversions
still produced the direct result under Mojo 1.0. A minimal runtime probe showed
direct=15361, inline-F32=15361, separate-call-F32=15360 for
`1.0004882812500002`; the source result is 15360. A no-inline F32 function now
preserves that rounding boundary. The complete cast comparison then passed.
This is a source-behavior correction, not a new rounding algorithm.

Reference executable, checksums, original source hashes and Cargo.lock:
[`tests/fixtures/rich-arrow-export`](../../tests/fixtures/rich-arrow-export/README.md).
The original reference code is independent of Akasha; Rust remains test-only.

## Verification

- Python module build passed after the rounding correction.
- **55 new Python tests passed**, covering types, nested masks/metadata, required
  fields, missing projection, stable empty schema, limits, snapshots, owned output
  after close, failure cleanup, the original IPC source fixture and all cast cases.
- **14 related native tests passed**: ten Arrow export/ownership tests and four
  shared payload tests. The two new ownership tests relocate a nested string
  grandchild before releasing its parents and exercise partial allocation failure.
  The subsequent change only preserves F16 rounding; ownership paths are unchanged.
- Full Python regression: **3,385 passed, 1 existing skip, 3 warnings** in
  81.19 seconds, including the 55 new tests and installed-header C Data ABI probe.
- Cast fixture, source metadata and Cargo.lock regenerated byte-for-byte. The
  common buffer owner was compared against commit `521427a`; its extracted
  implementation is unchanged (SHA-256
  `2e030cba5bd7cf9c4bb136051945aa8cd30ddd41ab72cb0801ff56d2de509734`).

Commands/logs are retained under `.build/rich-arrow-export-validation/`, including
both unsuccessful rounding comparisons and the minimal probe. The initial
resource-limit test selected the wrong physical row after an update; it now
selects the intended point by ID instead of assuming scanner ID order.
The first full regression had 3,384 passes and one failure because the ABI probe
still imported the moved internal buffer owner from `arrow_export`. Its import
now targets `arrow_buffers`; the complete rerun above passed. The original
failed run is retained alongside `python-full-final.log` and `provenance.json`.

No durable format or external C ABI changed, so their full suites were not rerun.
Native Linux, full performance gates, rich JSON extension, indexes, protocols,
Lance/table/transaction, UI, security, cluster and operations scope remain open.
