# AArch64 CRC and database lifecycle costs

A feature-gated CRC-32/ISO-HDLC implementation now uses AArch64 CRC32 instructions
for complete words and remaining bytes. The portable slicing-by-eight path stays
in use when the target lacks the instruction. Registers, checksum complements,
streaming boundaries, durable bytes and corruption checks are unchanged. See the
[design and compiler API constraints](../plans/2026-10-02-arm-crc.md).

The first prototype assembled each word through checked byte reads. Assembly
inspection showed repeated bounds checks, and its timings did not justify
adoption. The selected loop proves eight remaining bytes, then performs one
explicitly unaligned load. Actual protected-page tests exercise both ends of the
readable page, empty buffers and every length through 129. Bitwise oracles cover
16 alignments, varied registers and streaming boundaries. Numeric/page tests pass
for Apple M4, generic ARM64, explicit `+crc` and explicit `-crc`; five assembly
target cases also check Linux x86-64 compilation without CRC instructions.
No Linux execution gate is claimed.

Five rotating-order microbenchmark trials compare the selected path, the existing
portable block routine, the byte loop and installed zlib. Initial registers vary
on every repetition. The final portable comparator preserves the production
inlining contract; earlier raw experiments remain archived separately. At 64 MiB,
the selected / portable / zlib medians are **5.666 / 55.511 / 2.286 ms**. One-byte
input is .73 / .53 ns for selected / portable, while eight bytes is .79 / 2.73 ns.
This is a fixed microbenchmark, not an end-to-end speedup estimate; zlib remains
faster on large buffers and has not become a production linkage dependency.

Three alternating before/after pairs per corpus use identical closed,
cache-populated databases. Every worker checks its loaded native binary hash.
All **576 exact oracle checks** pass, and **576 ANN result lists**, IDs and
scores match. Initial setup is excluded from open timing.

## Integration and mixed workload

Full CPU integration passed **957 Mojo tests in 131 files, 23 crash tests in
eight files, all 344 Python tests**, the rebuilt C ABI client, and three rebuilt
examples. A child-compiler startup failure in the independent file-lease reader
was caused by an omitted Metal target in the validation launcher. The existing
wrapper corrected that invocation; only its failed file and unrun files were
resumed. Both the original failure and final successful logs are retained.
The native maintenance worker was unchanged and was not overwritten during tests.

Three serial alternating mixed-workload pairs per corpus each execute 32 blocks
of nine reads, eight replacements and flush, retaining an Arrow lease through
close. All **5,184 ranking audits**, 18 final reopen oracles and 18 lease checks
pass; every worker's loaded binary hash is checked. All 72 mode/version/trial
cells reach .95 recall with valid execution.

| Corpus / operation | Before median ms | After median ms | Paired ratio median (full range) |
|---|---:|---:|---:|
| Uniform 128D / flush p95 | 22.494 | 18.298 | .813 (.722–.816) |
| Uniform 128D / write + flush p95 | 29.338 | 25.436 | .846 (.792–.879) |
| Uniform 1536D / flush p95 | 53.781 | 31.803 | .596 (.581–.629) |
| Uniform 1536D / write + flush p95 | 78.168 | 57.075 | .706 (.701–.737) |
| Real 1536D / flush p95 | 54.795 | 32.895 | .599 (.592–.602) |
| Real 1536D / write + flush p95 | 70.158 | 48.818 | .688 (.675–.728) |

Each combined sample sums its own block's update and flush, before quantiles are
computed. Medians are across trial p95 values; ratios are paired trial values.
Write-only uniform 128D p95 regresses from 7.017 to 7.486 ms, with paired ratios
1.010–1.080. Uniform 1536D is nearly unchanged; real-data write-only ratios span
.949–1.013. These costs include WAL fsync at batch acceptance. No all-operation
speedup is claimed.

Post-write reopen medians are 118.780 → 95.633 ms, 208.378 → 147.912 ms, and
231.917 → 162.677 ms for uniform 128D, uniform 1536D and real 1536D respectively.
Paired ratios are .805 (.797–.812), .710 (.693–.715), and .699 (.695–.705).
The initial cloned databases lack the finalized overlay cache, so their first
open includes delta reconstruction and is a separate measurement. Its first
128D baseline outlier remains retained.

Queries show no consistent general improvement. For example, real-data
independent-filter QPS ratios are .970, 1.001 and .937; real selective ratios
range from 1.123 to 2.940. All raw samples remain included. These mixed query
observations must not be presented as a steady-state warm-query improvement.

audits**, 36 matched-recall cells and 18 final reopen oracles. Akasha's 9 retained
Arrow leases survive close; Qdrant has no matching Arrow API. The combined
update/flush comparison includes each engine's synchronization path; individual
update calls have different durability boundaries and are not equivalent throughput.

## File-data-cold open

A capability check established that the existing unprivileged `F_NOCACHE` copy
method works in this environment. It creates new task-owned inodes, fsyncs them,
and verifies each nonempty file with `mincore` after the complete directory has
been copied. It does not evict global caches or apply memory pressure. The 27
measured opens all begin with **zero resident input pages**. Before/after/Qdrant
order rotates over three trials so every version occupies each position once.
Source hashes are collected while copying; destination contents are never read
before the residency check and timed open. Source files, executable code and
runtime libraries may remain cached. SSD/controller caches are not controlled.

| Corpus | Before ms | CRC after ms | Qdrant ms | After/before paired median (range) | After/Qdrant paired median (range) |
|---|---:|---:|---:|---:|---:|
| Uniform 128D | 120.560 | 98.633 | 246.123 | .818 (.817–.832) | .408 (.400–.411) |
| Uniform 1536D | 291.545 | 229.781 | 383.271 | .799 (.764–.855) | .612 (.571–.625) |
| Real 1536D | 330.271 | 242.904 | 373.370 | .735 (.693–.755) | .658 (.565–.668) |

These are medians of three individual opens. The persisted directory sizes differ:
Akasha uses 17.33 / 118.83 / 118.80 MB, versus Qdrant 209.37 / 322.64 / 322.49 MB,
including each engine's existing log/segment/cache files. File inventories and
hashes are retained, including empty files. The same logical workloads, exact
oracles and closed ready indexes are used; this is not equal-bytes I/O throughput.

All **864 post-open exact oracle checks** pass. The original fixed-ef=128 ANN
sanity results are retained, including cells below .95 recall; before/after
Akasha IDs and scores match. A separate **untimed** audit then runs all 64 queries
per mode using the previously frozen refined-grid ef choices, with no new tuning
or replacement of cold timings. Its **2,304 result audits and 36 recall cells**
pass (.95 minimum target), with identical before/after Akasha results and valid
execution classifications. Qdrant's internal fallback remains unobservable.

This completes the file-data-cold open slice for these fixtures. It does not
establish sustained non-resident queries, a working set larger than a controlled
memory budget, or overall Qdrant parity. Network tests and Git index writes retain
their previously recorded sandbox restrictions. No new GPU/Linux execution gate
is claimed. Raw evidence is archived alongside this report.
