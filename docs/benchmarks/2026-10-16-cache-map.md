# Mapped derived-cache reads resolve the remaining short-open capacity failures

All 27 capped candidate workers complete, compared with 21/27 before. Both
1536-dimensional corpora change from three OOM kills to three successful
open/read/close runs at **128 MiB**. This closes those six failures in the
[previous short capacity diagnostic](2026-10-16-point-map-capacity.md).
Native macOS opening also uses 10–16% less peak process memory. Mixed-query
p95 regressions remain recorded below; full Qdrant acceptance is still open.

## Failure localization and change

Two isolated diagnostic builds add native phase markers to the current
checkpoint-mapped implementation. Each runs seven externally prepared jobs:
uniform-128 at 128 MiB, and both high-dimensional corpora at 6144/192/128 MiB.
The coarse probe reaches `collection.after_metadata` before both high-dimensional
128 MiB OOMs. The fine probe reaches `overlay.before_graph_decode` in both.
Its five completed workers reproduce the uninstrumented control responses.

Before graph decoding, the old cache reader reads the whole file, copies it
again to read the footer, makes a discarded body-sized copy to skip to the
footer, and copies the payload. In the real-1536 128 MiB fine trace, loading the
5,163,036-byte overlay envelope raises RssAnon from 108,504 to 123,516 KiB before
owned graph decoding starts. The process then dies during graph decoding.
These markers add Python allocation/I/O and can shift the failure threshold;
they localize work, not exact allocator ownership or production speed. The
uninstrumented paired matrix independently establishes the capacity effect.
The fine probe's initial compile failure (a raising marker in a non-raising
function) and its correction are retained; production contains no markers.

The pinned Qdrant source (`21db2f3ff95d50de3a2b88a741312c056fd1762d`,
`lib/segment/src/index/hnsw_index/graph_links/storage.rs`) keeps borrowable
mapped storage without materializing a second whole graph blob. Akasha applies
that bounded-read principle to its existing AKIC envelope: map the immutable
file, check total size and CRC, validate a 36-byte header, then copy only the
owned payload. The byte-array decoder also reads its footer through a borrow.
Both paths share header validation. Existing 512 MiB bounds, cache identities,
inner graph validation and authority binding remain enforced. Mapping/read/
corruption failures remain optional-cache misses. No format, public API,
search breadth, query planner, authority reranking or threshold changes.

## Controlled capacity result

The source baseline is `4bb982e` (engine `f2781df`); only
`storage/index_cache.mojo` changes in the candidate. Mojo 1.0.0 (`ed45d567`)
builds the candidate. The baseline library is the frozen prior point-map build.
Linux baseline SHA-256:
`2a11d86596c637aaafd52b41c96a3cbf7a9bf4697684d710c8719f22a35b7e28`.
Linux candidate SHA-256: `789005c77a9aa053e885437efdf484848cecb86cf4bd218693fe70717d5e0076`.
Image: `sha256:540414f50b96439a6ba1475b79b2e2dd2208e86ebef33e2fbf2a176a8f037d31`.

This is **emulated Linux x86-64 on the ARM Mac**, not native Linux. The same
three N=8192 Dot/F32 databases, configuration and graph/metadata files are used.
Three alternating before/after pairs run at 128/192/256 MiB, with one 6144 MiB
control pair per corpus. Each worker gets one CPU and zero swap. A separate
6144 MiB preparation container copies to fresh Linux-volume inodes, fsyncs and
requests FADV_DONTNEED, then exits. Preparation and measurement both verify zero
initial `.bin` residency. No builds, tests or compression overlap measurement.

All six controls complete. Capped completion is **21/27 → 27/27**. All 54
completed workers match both controls' exact and ANN zero-query responses
(108 ID/F32-bit checks). The six baseline failures are Docker-confirmed OOM
kills, exit 137, after `before_open`. There are no candidate failures,
preparation failures or timeouts.
