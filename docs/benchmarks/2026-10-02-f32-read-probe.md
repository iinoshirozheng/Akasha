# Bounded F32 reads and cached-open cost

An isolated implementation copied complete little-endian F32 tapes into new owned
lists using the installed standard library. It retained position/length/overflow,
checksum, format and vector validation. All **58 tests in eight files** passed:
raw bits, unaligned input, truncation, ownership and existing segment/WAL/HNSW
fixtures and corruption checks. [Proposal](../plans/2026-10-02-f32-bulk-read.md).

After verifying the corrected prototype binary, all nine public cached-open
pairs improved. The four-file implementation is adopted: owned/borrowed reader,
legacy segment and WAL vectors, and owned F32 HNSW snapshot rows. Formats,
checksums and validation requirements are unchanged.

| Corpus | Before median ms | Correct prototype median ms | Paired after/before median (range) |
|---|---:|---:|---:|
| Uniform 128D | 121.169 | 108.086 | .894 (.886–.899) |
| Uniform 1536D | 356.089 | 256.430 | .716 (.715–.720) |
| Real 1536D | 372.562 | 270.162 | .721 (.716–.729) |

This valid run used three alternating fresh-process pairs per corpus and
identical closed cache-populated databases. All 18 loaded binary hashes match
their expected version, and the new artifact contains the unique bulk-reader
diagnostics. Every open passed 32 exact independent Float64 checks and 32
approximate queries; before/after IDs and public scores matched exactly, for
576 exact checks and 576 approximate comparisons. The OS cache was present.
No compilation, tests or compression overlapped measurement. This does not
establish cold/nonresident performance or Qdrant parity.

## Excluded initial comparison

The **initial public comparison is invalid and excluded**. Its build used the
production `src/bindings/python_module.mojo` entry with a prototype `-I` directory;
the entry package root resolved production imports instead. The resulting library
contained neither of the new reader's unique error strings. The corrected build
uses `.build/f32-reader-probe/src/bindings/python_module.mojo` and contains both.
The invalid three-pair timings are retained below for traceability, without any
conclusion about F32 decode performance:

| Corpus | Before median ms | Prototype median ms | Paired after/before median (range) |
|---|---:|---:|---:|
| Uniform 128D | 116.297 | 117.250 | 1.017 (.995–1.024) |
| Uniform 1536D | 354.536 | 363.531 | 1.020 (1.018–1.036) |
| Real 1536D | 376.245 | 374.398 | .991 (.986–1.015) |

Those opens also passed their query audits, but validation of results alone
cannot establish that the intended implementation was measured. Both build
commands, old/new artifacts' hashes, marker checks and all timing samples remain
available. The earlier rejection based on this invalid comparison was withdrawn.

## Stage diagnosis

An earlier phase-only build of current production, with three runs per corpus,
showed 1536D authority recovery around 147 ms, segment read/decode around 143 ms,
and recovered-entry application around 3 ms. Base HNSW loading took about
122/132 ms, delta cache loading about 36/38 ms, fingerprinting about 26 ms and
metadata about 14 ms. Those are diagnostic stage timings, not isolated F32
decoding measurements.

A second diagnostic separates the stages. Uniform/real 1536D median total
segment file reads were 13.560/13.425 ms, CRC 23.422/23.162 ms and parse+CRC
124.874/122.578 ms. The base's CRC took 22.214/22.488 ms and structural validation
98.264/106.416 ms. Instrumentation overhead is included. These counters motivated
checking the unexpected first result's build provenance before rejecting the
proposal; they also identify the mapped structural audit as a remaining open cost.

## Production validation

After adoption and formatting, **120 Mojo tests in 14 files and 20 crash tests
in five files passed**. These cover the new reader, existing checksum/borrowed
reader contracts, legacy recovery, persistent documents/batches/HNSW, overlay
cache/base recovery/rebuild publication, point migration/recovery, operations,
checkpoint order and backup publication. The earlier isolated codec/fixture
run passed 58 tests; these are separate stages with overlapping coverage, not a
fresh full-repository suite.

Rebuilt Python passed **317 tests**, three existing warnings, 12.48 s. Rebuilt
C library and external C ABI client passed. The final production patch is 141
lines of diff across four source files before adding the new test.

Optional address sanitization could not execute on this toolchain.
`pixi run mojo run --sanitize=address --target-accelerator=metal:4
--target-cpu=apple-m4 -I src tests/mojo/test_f32_bulk_read.mojo` failed to resolve
ASan JIT symbols. Building the same test with `mojo build --sanitize=address`
failed to link `___asan_version_mismatch_check_v8`. Neither is counted as an
ASan test pass. Both failures and all successful ordinary checks are retained.

## Final production mixed workload

Three alternating saved-before/current-after pairs per corpus passed all **5,184
query audits, 72 recall cells, 18 exact reopen oracles and 18 Arrow leases**.
Minimum mean recall was .952778. This is the established resident 32-block mixed
workload with writes, flush, compaction and a retained Arrow root.

| Corpus | Cached reopen before→after ms | Paired ratio median (range) | Write+flush p95 before→after ms | Paired ratio median (range) |
|---|---:|---:|---:|---:|
| Uniform 128D | 125.297→117.101 | .927 (.927–.935) | 29.650→29.625 | .999 (.995–1.011) |
| Uniform 1536D | 352.440→253.315 | .718 (.715–.735) | 78.874→77.466 | .990 (.960–1.005) |
| Real 1536D | 367.490→269.113 | .732 (.729–.737) | 69.761→72.080 | 1.037 (.989–1.065) |

Each latency column is the median of per-trial values; the ratio is the median
of paired ratios. Combined write+flush measures each block's actual sum.
Write-only p95 paired medians were .966/.994/1.061, and flush p95
1.001/.996/1.007. The real write-only regression and slower combined samples are
retained; this change claims a reopen benefit, not a write benefit.

Query QPS after/before medians (all/correlated/independent/selective) were
.998/.967/1.012/.914 at 128D, 1.013/.961/1.022/.853 at uniform 1536D, and
.988/.997/.989/.974 on real data. No query speedup is claimed. The largest real
after sample was correlated/block 13 in trial 2, 13.306 ms, versus that pair's
ordinary samples; it is not removed or attributed to maintenance without a
profile. The first old 128D no-cache open was also unusually slow, retained in
the raw report. Initial no-cache opens and post-write cached reopen are reported
separately.

This paired run does not remeasure Qdrant. The prior Qdrant warm/mixed gaps and
the external nonresident/network/Git gates remain open; see the
[latest direct comparison](2026-10-02-hnsw-delta-scan.md).
