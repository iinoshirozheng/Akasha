# Native-field IVF acceptance

IVF-flat is available through Mojo `IvfOptions`, Python `mode="ivf"`, Arrow
results and field-fusion branches. It uses existing deterministic Lloyd training
with one full-dimensional L2 codebook. Selected lists are scored from native
owners in Float64, including F32/F16/BF16/I8/U8 and dot/L2/cosine. The catalog and
authoritative storage format do not change. See the [design](../plans/2026-10-01-field-ivf.md)
and [public API](../python-api.md).

Three Mojo tests cover all 15 dtype/metric pairs, full-probe exact equality,
filters, negative IDs/ties, absent fields, limited probes, cache keys,
old/new roots, close, deadline failure/retry and eight concurrent first readers.
The 25 IVF Python tests cover an independent NumPy Float64 oracle, Arrow columns,
fusion, mutations/flush/reopen, option validation and effective list/probe bounds.
The existing control test also runs IVF through both Python and Arrow for limits,
cancellation, deadlines and retry. The rebuilt extension passes all **264 Python
tests**. The refactored shared row/projection helpers pass the three named-HNSW
and two named-sparse tests.

This environment's compiler cannot automatically discover Metal hardware inside
the sandbox. Explicit `--target-accelerator=metal:4 --target-cpu=apple-m4` compiles
and runs on the host M4 Pro. Compiler-contract tests use an untracked local
launcher that adds only the accelerator option, preserving their explicit CPU
and target-triple tests. No project target defaults were changed.

## Probe curve

`benchmarks/field_ivf.py` ran alone on the rebuilt extension with 2,048 rows,
64 dimensions, K=10, 32 lists, eight training iterations and seed 718. Small
integer inputs are exactly representable in every native dtype. Each cell has
three passes of 32 queries after three warmups, with unfiltered and 25% filters.
Oracle calculation and statistics retrieval are outside timings. All 180 cells
retain raw latencies, counters and recalls. Every full-probe query matches both
the independent oracle IDs and Float64 scores.

Examples for F32, unfiltered (QPS / Recall@10):

| Metric | 1 probe | 4 probes | 16 probes | 32 probes |
| --- | ---: | ---: | ---: | ---: |
| Dot | 17,567 / .1000 | 11,773 / .3281 | 5,165 / .7687 | 3,039 / 1.0000 |
| L2 | 17,517 / .1313 | 11,217 / .3625 | 4,840 / .8250 | 2,972 / 1.0000 |
| Cosine | 17,409 / .1281 | 11,628 / .3813 | 5,058 / .8219 | 2,949 / 1.0000 |

First build plus query takes 52.21–56.31 ms across the 15 dtype/metric cases.
Low probe counts fail a .95 recall target on this uniform corpus; their speed
is not a parity claim. The U8/L2 one-probe timing outlier is retained unchanged.
The raw archive is [here](results/2026-10-01-field-ivf.json.gz).

## Ownership and limits

The artifact retains 24 bytes per row location, one 8-byte membership ordinal
per row, and 4 bytes per centroid component as logical array payload: 73,728
bytes for this workload, excluding List capacity slack, container headers,
locks and allocation metadata. Source inspection establishes this layout;
these are not allocator measurements. Temporary training inputs contain another
524,288 logical F32 bytes plus row descriptors and trainer workspaces, released
after building. The benchmark separately records real process peak RSS before
and after build. Its high-water marks include Python inputs and prior cells and
cannot be interpreted as retained index bytes or independent per-cell memory.

Each immutable root owns its artifacts. Writes/reopen require another first-use
build; there is no durable IVF sidecar. Query controls bound candidate count and
cooperatively stop training. L2 coarse selection is approximate for all metrics;
filtered limited-probe queries can return fewer than K without expanding work.
Qdrant parity, mixed writes/maintenance and non-resident measurements remain
separate M5/M6 gates.
