# Block CRC and checkpoint costs

CRC-32/ISO-HDLC now processes larger buffers eight bytes at a time, retaining
the byte loop below 32 bytes. Mapped HNSW checksum reads validate their complete
range once and borrow it synchronously. Formats, registers, final complements,
corruption checks and persisted checksum values are unchanged. See the
[design and library comparison](../plans/2026-10-02-block-crc.md).

The production microbenchmark compares the prior byte loop, current helper and
installed zlib 1.3.2. Five rotating-order trials vary the initial register for
every repetition. Zlib also checks alignment and streaming results independently.
At 64 MiB, median times are 129.238 / 28.352 / 2.541 ms respectively. Production
inlining removes the roughly one-nanosecond short-input overhead seen in the
earlier prototype: 1 byte is .52 ns for both loops; 31 bytes is 21.4 / 21.3 ns.
Zlib remains faster, but adding its production linkage/runtime contract is a
separate decision; no implicit dependency was introduced.

Three alternating fingerprint pairs use 8192 rows, three repetitions per sample,
and identical checksums before/after. Median per-fingerprint time is 12.501 to
5.593 ms at 128D and 117.736 to 42.693 ms at 1536D. This includes encoding work,
unlike the raw CRC microbenchmark. The extra lookup table contains 8 KiB of
entries; total binary/RSS growth was not measured.

## Database lifecycle measurement

`benchmarks/bounded_batch.py --phases mixed` compares the saved pre-CRC package
with the rebuilt current package. Both already contain bounded batches and
sorted postings. Three corpora each run three serial alternating pairs from
copies of the same closed baseline: 32 blocks of nine reads, eight replacements
and flush, retaining an Arrow lease through close. No builds/tests overlap.
OS cache remains present; these are resident binding measurements.

All 5,184 returned rankings pass live-ID/filter/recall audit; all 72
mode/version/trial cells reach .95 recall with valid execution. All 18 final
reopen oracles and Arrow leases pass. Raw inventories retain compaction and
retirement evidence.

Times below are the median of three per-trial p95 values. The final column is
the median and complete range of paired after/before ratios, not a pooled p95.

| Corpus / operation | Before ms | After ms | Paired ratio, median (range) |
| --- | ---: | ---: | --- |
| Uniform 128D / flush | 33.977 | 18.430 | .542 (.460–.736) |
| Uniform 1536D / flush | 149.833 | 60.935 | .403 (.392–.426) |
| Real 1536D / flush | 145.977 | 60.834 | .417 (.374–.504) |
| Uniform 128D / write + flush | 41.693 | 25.565 | .611 (.551–.784) |
| Uniform 1536D / write + flush | 173.049 | 84.610 | .497 (.464–.498) |
| Real 1536D / write + flush | 161.688 | 76.406 | .473 (.435–.555) |

Each combined sample adds its own block's write and flush; it does not add two
quantiles. Akasha includes WAL fsync in batch acceptance, while Qdrant Edge's
separate flush synchronizes WAL/segments. Individual update calls must therefore
remain labeled as API costs, not durability-equivalent throughput comparisons.
This experiment compares two Akasha versions and does not remeasure Qdrant.

Median post-write reopen times are .745 to .711 seconds at 128D, 2.012 to 1.775
seconds at uniform 1536D, and 1.700 to 1.453 seconds on real data. Paired ratios
are .961 (.934–.967), .884 (.879–.906), and .853 (.845–.862).
The first pre-change 128D open took 1.241 seconds versus .808/.800 in its other
trials; it remains in the report. No warm-query, cold-cache or parity claim
follows from these lifecycle gains.

## Query-path diagnostics

Separate diagnostics measured the existing Python list-to-F32 conversion at a
median 1.036 µs for 128D and 11.823 µs for 1536D. Replacing mapped SIMD-chunk
checks with a single full-row check did not produce consistent high-dimensional
gains in seven alternating passes on each corpus. Every base-only candidate ID
and distance matched. Neither experiment justifies a production query change;
[all sources and samples](results/2026-10-02-query-path-probes.json.gz) are retained.
