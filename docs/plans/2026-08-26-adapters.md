# Phase 8: Python, HTTP, and Arrow Adapters

## Goal

Expose the completed Mojo kernel without duplicating storage or query semantics
in Python.

## Boundaries

- A Mojo `PythonModuleBuilder` extension owns `PersistentCollection` values and
  exposes lifecycle, mutation, lookup, dense, approximate, sparse, and hybrid
  calls.
- Python dataclasses provide stable typed request/result models and map kernel
  exceptions into an Akasha exception hierarchy.
- `LocalDatabase` is an in-process adapter over the compiled extension; tests
  can inject the same narrow kernel protocol.
- FastAPI routes call `LocalDatabase` and never implement scoring or durability.
- Arrow support accepts/returns documented column dictionaries. It copies and
  validates buffers; the placeholder C Data module explicitly does not claim
  zero-copy ownership.

## Delivery

1. Build and smoke-test the Mojo Python extension.
2. Implement Python models, exception mapping, local collection registry, and
   copying Arrow batch conversions.
3. Add health, collection lifecycle, mutation, get, flush, and search routes.
4. Add Python and HTTP functional tests against temporary collections.
5. Document usage, run all Mojo/Python/crash/build checks, merge, and push.
