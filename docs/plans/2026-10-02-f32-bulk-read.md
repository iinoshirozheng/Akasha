# Bounded owned F32 tape decoding

**Disposition: adopted after the corrected comparison.** The initial comparison used
an incorrect binding entry path and did not include the prototype implementation.
Those numbers are excluded. After correcting the copied entry and verifying
distinct binary markers, all nine pairs improved (about 11%/28%/28% medians), with
identical results. See the [measurement](../benchmarks/2026-10-02-f32-read-probe.md).

Current cached-open phase measurements isolate about 143 ms of segment read/
decode in each 1536D corpus, out of about 353/368 ms total. Applying recovered
entries takes only about 3 ms. Base HNSW loading is a separate 122/132 ms cost.
The isolated candidate changes F32 decoding, leaving that mapped base path alone.

Add a shared bounds-checked `read_f32s(count)` operation to the existing owned and
borrowed binary readers. Check position and `count <= remaining // 4` before
allocation, multiplication or pointer construction. Return an empty list for zero
elements, including at EOF. On little-endian hosts, allocate an owned F32 list
and initialize every byte with the standard byte-wise memory copy; source
alignment is unrestricted and the new destination cannot overlap it. Big-endian
hosts retain explicit little-endian scalar assembly. Failed bounds checks leave
the reader position unchanged. Every IEEE bit pattern survives decoding; callers
retain responsibility for finite/prepared-vector validation.

Use this operation for legacy segment vectors, legacy single/batch WAL vectors
and F32 owned HNSW snapshot rows. Preserve all checksum, length, format, sequence,
payload, graph structure and vector validity checks. Compact snapshot scalars
keep their existing decoding. No format or public database API changes.

The installed standard library already supplies the required allocation/copy
operations. Its local 1.0.0 List source is in the earlier borrowed-WAL research
artifact. Official [List](https://mojolang.org/docs/std/collections/list/List/)
and [unsafe_memcpy](https://mojolang.org/docs/std/memory/memory/unsafe_memcpy/)
contracts were consulted; the project compiler confirms the API. The live List
page is 1.1.0, so documentation alone is insufficient. Local Qdrant dense vector
storage similarly uses bulk byte conversion/copy; Akasha's durable little-endian
format still requires its own explicit endian decision.

Acceptance: raw-bit tests (signed zero, subnormal, extrema, infinities and NaN
payloads), offsets 0–7, zero/short/1536-element tapes, every short truncation,
negative/extreme lengths, unchanged error position and ownership after source
mutation. Existing segment/WAL/HNSW compatibility and corruption tests must
pass. Compare three alternating fresh-process cached-open pairs per corpus with
exact independent oracles and identical approximate IDs/scores, then adopt only
if supported by measurement. After adoption run affected recovery/crash, Python
and C integration. Keep the prototype, phase measurements and all trials. No
build/test/compression may overlap performance measurements.
