# Preserve CRC bytes while reducing checkpoint work

The mixed workload exposes 140–177 ms high-dimensional flush p95. A direct
8192-point fingerprint measurement, using three repetitions and no concurrent
builds/tests, takes 12.914 ms at 128D and 123.751 ms at 1536D. The latter includes
serialization and CRC of about 48 MiB of vector bytes. This new lifecycle evidence
justifies revisiting the byte-table CRC retained by the earlier A12 audit.

The installed dependencies include zlib 1.3.2. A scoped `OwnedDLHandle` benchmark
calls its official `crc32_z` ABI as an independent oracle and performance ceiling.
The [zlib manual](https://zlib.net/manual.html) specifies its finalized running
checksum and `size_t` input length; Akasha's public streaming helper instead keeps
the unfinalized register, so the probe complements before and after that call.
Mojo's current hashlib has no matching CRC-32/ISO-HDLC implementation. Production
keeps the existing pure Mojo API: introducing a zlib runtime/linkage requirement
would also change standalone Mojo invocation and packaging contracts. The library
is measured but is not added as an implicit deployment dependency.

The selected change extends the existing lookup algorithm with eight positions
per block, derived from the same reflected polynomial `0xEDB88320`. Assemble
bytes explicitly in little-endian order, XOR eight table contributions, then
process the tail with the original byte loop. For fewer than 32 input bytes,
retain the original loop. The 32-byte crossover is fixed from isolated paired
measurements, independent of database contents, metrics, or query results.
The added table contains 8 KiB of compile-time entries; this is logical table
size, not a measurement of total generated binary or resident memory.

The unbranched prototype speeds larger inputs roughly fourfold but regresses
short inputs. The crossover prototype reduces the 32-byte cost from 24.62 to
14.84 ns and 64 MiB from 139.815 to 31.437 ms. Tiny inputs still show about one
nanosecond of dispatcher overhead. Zlib is substantially faster (64 MiB: 2.904 ms)
and remains a future option if its explicit linkage/deployment contract is
adopted. Preserve both prototype reports and the slower samples.

Mapped HNSW checksums previously called a checked byte getter for every byte.
`MappedFile.checksum(offset, length)` now validates the full range with the
existing overflow-safe `checked_slice`, borrows a Span only for the synchronous
checksum call, and returns a number. Empty mappings are handled without accessing
a missing base pointer. Closed/range/overflow checks remain; neither pointers nor
Spans escape. Both HNSW load paths retain their checksum-before-layout checks,
stale-identity classification and corruption errors.

The required gates are independent bitwise CRC oracles across 16 alignments,
block/tail/crossover boundaries, four initial registers and split streaming;
zlib parity; empty/closed/invalid mmap ranges; every durable-format fixture and
crash/recovery suite; rebuilt Python/C ABI/examples; and paired lifecycle timings
against the saved pre-CRC package. No on-disk format or acceptance rule changes.
