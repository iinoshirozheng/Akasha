# Native field IVF retrieval

The remaining M5 index work includes an IVF path. The existing named-field
query boundary already owns an immutable read root and returns native F64
scores. Use that boundary; keep authoritative bytes and the catalog format
unchanged.

## Evidence and selected design

The local Faiss reference (`reference/faiss/faiss/IndexIVF.cpp`, `search` and
`search_preassigned`) selects coarse partitions before scanning their inverted
lists. Akasha already has deterministic Lloyd training in `PqCodebook.train`;
one subquantizer gives full-dimensional L2 centroids. Reuse that implementation
and its cancellation checks rather than add another trainer or dependency.

Implement IVF-flat with L2 coarse partitioning and native field scoring inside
selected lists. This is an approximate candidate selection strategy for dense
dot/L2/cosine; probing every list must exactly equal the native exhaustive
oracle. No quantized reconstruction is used to score results. Explicitly report
the probe count and visited/reranked row counts. A selective filter can leave
fewer than K results at a limited probe budget; do not secretly scan all lists
or describe that case as a complete exact result.

Root-owned artifacts are keyed by field ID, requested list count and training
iterations. Probe count, K and filters do not change training. Publish only a
complete immutable artifact; concurrent readers share it and failed builds can
retry. Build temporary F32 training inputs from native owners, retain only
centroids, row locations and list membership. Old snapshots keep their index
through writes/close; new roots cannot reuse stale membership.

Use explicit query-time IVF options, like the existing query-time PQ training
configuration. Do not assign a new durable catalog index tag without a versioned
format proposal. Keep HNSW's ef/rerank controls separate and reject mixed options.
Expose the same operation in Mojo, Python, Arrow and multi-field query branches.

## Delivery and verification

1. Artifact and kernel: native dtype/metric coverage, full-probe oracle parity,
   deterministic ties/negative IDs, missing fields, filters and limited probes.
2. Root lifecycle and public API: repeated/concurrent readers, changed training
   keys, mutations, old/new snapshots, close/reopen, failed/cancelled builds,
   bounds and empty collections. Validate options before retaining state.
3. Python/Arrow/fusion: independent NumPy Float64 oracle, matching result columns,
   strict option types, budgets and one captured root for all fusion branches.
4. Measure build separately from repeated warm searches; record probe/recall
   curves and retained memory. This is not evidence of Qdrant parity.

The first implementation bounds requested list count to 1..256, matching the
existing trainer. Training iterations must be positive. Documentation must
state this bound and the cold-build/root-cache behavior.
