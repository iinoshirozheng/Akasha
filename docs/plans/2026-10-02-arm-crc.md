# Feature-gated CRC-32/ISO-HDLC acceleration

The existing slicing-by-eight implementation is correct and portable, but CRC
still contributes to checkpoint fingerprinting and reopening mapped graphs.
The installed zlib has already demonstrated a lower cost; adding runtime library
linkage would change standalone Mojo and packaging contracts. This experiment
instead uses the CPU CRC instruction through Mojo's existing LLVM intrinsic API.

Use `llvm.aarch64.crc32x` for complete eight-byte words and `crc32b` for the
remaining bytes. The [LLVM intrinsic definitions](https://raw.githubusercontent.com/llvm/llvm-project/main/llvm/include/llvm/IR/IntrinsicsAArch64.td)
distinguish these IEEE-polynomial operations from CRC32C. Keep the existing
initial register, complement, streaming API and every persisted checksum byte.
No dependency, file format, migration or configuration switch is introduced.

Dispatch at compile time only when the target triple is AArch64, native byte
order is little endian, and the actual target `crc` feature is enabled. All
other builds retain the existing portable algorithm. Mojo 1.0 lacks a public
architecture/CRC predicate. Its `_triple_attr` is already used by MappedFile;
`CompilationTarget._has_feature` is the underlying stdlib feature predicate.
The [upstream implementation](https://raw.githubusercontent.com/modular/modular/main/Mojo/stdlib/std/sys/info.mojo)
provides context, while the locked 1.0.0 compiler is the authority: probes verify
Apple M4, generic ARM64, explicit `+crc` and explicit `-crc`. CPU model names or
NEON alone are insufficient. Keep the compiler API dependency documented and
covered by target-compilation tests when upgrading Mojo.

The first prototype's individual Span byte accesses retained repeated checks
and did not deliver adequate gains. The candidate loop proves eight remaining
bytes before an explicitly unaligned 64-bit load. Its pointer is used only within
the borrowed call; no load occurs outside that proven range and no pointer escapes.
An independent bitwise oracle, all alignments/split points, and real protected
pages verify empty buffers, tails and both ends of a readable page. Assembly
checks require the intended instructions only for enabled AArch64 targets and
exclude them for generic/disabled ARM64 and Linux x86-64.

Acceptance requires the existing format/corruption/crash suites, full CPU and
Python integration, rebuilt C ABI/examples, and measured public cached reopen
and mixed read/write/flush operations against the saved current baseline.
Microbenchmark register values vary on every repetition, all variants retain the
same inlining contract, and installed zlib independently checks CRC bytes.
Public trials alternate execution order and verify the loaded binary hash and
exact/ANN result equality. Benchmarks do not overlap builds or tests. OS-cache
presence remains explicitly labeled; this does not close non-resident, Linux
execution, distributed-network or Qdrant parity gates.
